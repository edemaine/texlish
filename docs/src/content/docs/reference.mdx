## Sections

Similar to Markdown
[headers](https://daringfireball.net/projects/markdown/syntax#header) /
CommonMark [ATX headings](https://spec.commonmark.org/0.31.2/#atx-headings),
plus `*` for unnumbered sections.

<Example src={`
  # Introduction
  ## Background
  ### Aside
  #* Acknowledgments
`}/>

`!` goes up a level above section, while `.` goes down to the paragraph level:

<Example src={`
  !!# Beginning
  !# Introduction
  .# Results.
  .## Part 1.
`}/>

## Emphasis

Similar to Markdown
[emphasis](https://daringfireball.net/projects/markdown/syntax#em) /
CommonMark
[emphasis and strong emphasis](https://spec.commonmark.org/0.31.2/#emphasis-and-strong-emphasis)
(but only with `*`s, no `_` syntax).

<Example src={`
  *italic*
  **bold**
  ***bold italic***
`}/>

You can also redefine the meaning of these symbols:

<Example src={`
  ::styles
    * = \\textit
    ** = \\textsf
    *** = \\texttt
  *italic*
  **sans-serif**
  ***teletype***
`}/>

Equivalent `::config` form:

<Example src={`
  ::config
    styles:
      * = \\textit
      ** = \\textsf
      *** = \\texttt
  *italic*
  **sans-serif**
  ***teletype***
`}/>

To use the LaTeX character `*`, wrap it in braces
(so that pairs of emphasis characters aren't in the same group):

<Example src={`
  {*}not italic{*}
  {**}not bold{**}
`}/>

## Smart Quotes

ASCII single and double quote characters `'`/`"` become TeX opening/closing
quote ligatures, while apostrophes in words stay apostrophes:

<Example src={`
  "Double quotes"
  'Single quotes'
  "Outer 'inner'"
  Don't change apostrophes' directions.
`}/>

If you need a lone opening or closing quote, use an empty group to simulate
the surrounding context:

<Example src={`
  before "{} after
  before {}" after
`}/>

In more complex settings, you can use explicit `\lq` (`‘`), `\rq` (`’`),
`\ldq` (`“`), and `\rdq` (`”`) commands to choose your quote.

You can customize the output for opening and closing quote characters
using `::config quotes`.  For example, to use French guillemets like
«&nbsp;Bonjour&nbsp;»:

<Example src={`
  ::config
    quotes:
      ":
        open = \\guillemotleft~
        close = ~\\guillemotright
  "Bonjour"
`}/>

Or to get German low/high quotes like „Er sagte ‚Hallo‘.“:

<Example src={`
  ::config
    quotes:
      ":
        open = \\quotedblbase
        close = \\textquotedblleft
      ':
        open = \\quotesinglbase
        close = \\textquoteleft
  "Er sagte 'Hallo'"
`}/>

Quote output ending in a LaTeX control word automatically gets `{}` appended.
The same settings can be written with dotted keys like `quotes.".open`.

Smart quotes can be fully disabled with `::config -smartQuotes`,
`::config -markdownCompat`, or `::config latexCompat`.
When disabling, you probably also want to disable or customize
[Markdown-style code](#code) to restrict to three or more backticks,
so that one or two backticks can be used for opening quotes.

## Lists

Similar to Markdown [lists](https://daringfireball.net/projects/markdown/syntax#list) /
CommonMark [list items](https://spec.commonmark.org/0.31.2/#list-items),
but with less strict requirements on indentation.

<Example src={`
  - This is an item.
  - This is a longer item that
    continues on the next line.
`}/>

<Example src={`
  * This is an item.
  * This is a longer item that
    continues on the next line.
`}/>

<Example src={`
  1. This is an item.
  2. This is a longer item that
    continues on the next line.
`}/>

<Example src={`
  The algorithm works as follows:
  1. Initialize
  2. For each step:
    * Do the step
    * Continue
`}/>

Markdown-style lists can be disabled with `::config -markdownLists`
or `::config -markdownCompat`.

## Label/Ref

<Example src={`
  @=thm:main
  @thm:main
  @#thm:main
`}/>

If your label needs spaces or trailing punctuation, put it in quotes or braces:

<Example src={`
  @='thm main'
  @"thm main"
  @{thm main}
  @#'thm main'
`}/>

If you want to use a custom `\ref` system, such as `cleveref`, you can
override the meaning of these symbols:

<Example src={`
  ::styles
    @ = \\cref
    @# = \\cpageref
  @thm:main
  @#thm:main
  @thm:main,thm:other
`}/>

To use the LaTeX character `@` (that's not part of an [email link](#links)),
wrap it in braces:

<Example src={`
  To give feedback, {@}me
`}/>

  [[paper1, paper2]]
`}/>

## Footnotes

Similar to GitHub Markdown-style
[footnotes](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/using-footnotes),
you can define footnote content once with `[^id]:`
and insert markers with `[^id]`.

<Example src={`
  This is a problem[^false], but not too bad[^true].
  [^false]:
    This is actually not true.
    See Figure @fig:example.
  [^true]: This is actually true.
`}/>

The first marker expands to `\footnote{\protect\label{footnote:id} ...}`. Later markers
re-use the same footnote number with `\footref{footnote:id}`, and
`@^id` references that generated label directly as a number (no superscript).

<Example src={`
  This is first[^count].
  [^count]: But who's counting?

  See footnote @^count for details.[^count]
`}/>

Numeric IDs are disposable: all matching markers since the previous definition
bind to the next matching definition in document order. This lets each
paragraph re-use simple IDs like `[^1]`, without having to think up a name.

<Example src={`
  First paragraph[^1], again[^1].
  [^1]: First note.

  Second paragraph[^1].
  [^1]: Second note.
`}/>

You can also use Texlish footnote notation to specify authors and affiliations
(in default LaTeX document classes where `\footnote` works like `\thanks`).

<Example src={`
  \\author: Alice[^MIT] \\and Bob[^MIT]
  [^MIT]: Massachusetts Institute of Technology
`}/>

## Links

Similar to Markdown
[automatic links](https://daringfireball.net/projects/markdown/syntax#autolink) /
CommonMark [autolinks](https://spec.commonmark.org/0.31.2/#autolinks),
you can write URLs and email addresses in angle brackets.

<Example src={`
  <https://texlish.org>
  <edemaine@mit.edu>
`}/>

Texlish even produces a correct `mailto:` link in the common brace format
for writing multiple email addresses at the same domain:

<Example src={`
  <{edemaine,mdemaine}@mit.edu>
`}/>

To customize the visible text of a link, use Markdown
[inline links](https://daringfireball.net/projects/markdown/syntax#link) /
CommonMark [links](https://spec.commonmark.org/0.31.2/#links):

<Example src={`
  [Texlish](https://texlish.org)
`}/>

Texlish uses `\protect` in case links appear in a moving argument.

Markdown links can be disabled with `::config -markdownLinks`
or `::config -markdownCompat`.

## Code

LaTeX normally uses `` ` `` for opening quotes. In Texlish,
[smart quotes](#smart-quotes) let you use straight ASCII quotes `'`/`"`
instead, freeing up backticks `` ` `` for Markdown-style code.
Similar to Markdown
[inline code](https://daringfireball.net/projects/markdown/syntax#code) /
CommonMark [code spans](https://spec.commonmark.org/0.31.2/#code-spans),
matching backtick runs compile to LaTeX `\verb`:

<Example src={`
  Write \`$x^2$\` to produce $x^2$.
  Use \`\` \`literal backticks\` \`\` to write code.
`}/>

Code-span line endings and following indentation become a single space.
If the code starts and ends with a space, exactly one space gets stripped
from each end (like CommonMark), making it easier to write literal backticks.

Fenced code blocks use three or more backticks and compile to a
`verbatim` environment by default:

<Example src={`
  \`\`\`
  x < y
  \`\`\`
`}/>

If the opening fence is indented, up to that much indentation is removed from
each content line, following CommonMark:

<Example src={`
  Example:
    \`\`\`
      if x:
        y()
    \`\`\`
`}/>

You can customize both using `::styles`. For inline code commands, the
`::styles` key is the backtick run. For fenced blocks, add a `*`.

<Example src={`
  ::styles
    \`\` = \\Verb
    \`\`\`\`* = lstlisting
  \`\`inline\`\`
  \`\`\`\`
  block
  \`\`\`\`
`}/>

Fenced code blocks can specify an info string, such as a language name.
Then you can customize the environment for that info string with `::styles`.
Style values can be a plain environment, a Texlish-style `: environment`,
or a LaTeX-style `\begin{environment}`:

<Example src={`
  ::styles
    \`\`\`py = : lstlisting[language=Python]
  \`\`\`py
  print("hello")
  \`\`\`
`}/>

If a fenced code block starts with an optional argument, Texlish passes it to
the selected environment:

<Example src={`
  ::styles
    \`\`\`* = lstlisting
  \`\`\`[numbers=left]
  x
  \`\`\`
`}/>

Backticks can be disabled with `::config -markdownBackticks`
or `::config -markdownCompat`.
Set `markdownBackticks` to an integer `n`
to enable only runs of `n` or more backticks:
For example, if you prefer traditional TeX backtick quotes instead of
[smart quotes](#smart-quotes), you can keep one or two backticks for opening
quotes and use three or more for code:

<Example src={`
  ::config markdownBackticks=3
  \`single quotes'
  \`\`double quotes''
  \`\`\`code\`\`\`
`}/>

## Horizontal Rules

Similar to Markdown
[horizontal rules](https://daringfireball.net/projects/markdown/syntax#hr) /
CommonMark
[thematic breaks](https://spec.commonmark.org/0.31.2/#thematic-breaks),
a line of three or more hyphens (with possible spaces in between)
draws a horizontal separator:

<Example src={`
  Before
  ---
  After
`}/>

The default expansion is `\medskip\hrule\medskip`.
You can customize with `::styles`.

<Example src={`
  ::use dashrule
  ::styles
    --- = \\bigskip\\hrule\\bigskip
    ---- = \\bigskip\\hrule\\medskip\\hrule\\bigskip
    - - - = \\medskip\\noindent\\hdashrule{\\linewidth}{0.4pt}{2pt 2pt}\\medskip
  ---   % single
  ----  % double
  - - - % dashed
`}/>

Horizontal rules can be disabled with `::config -markdownHorizontalRules`
or `::config -markdownCompat`.

## LaTeX Commands

`\command:` makes it easier to specify commands with arguments.
The argument can be on the same line and/or on indented lines.

<Example src={`
  \\title: The Paper \\\\
    Subtitle
`}/>

<Example src={`
  \\footnote:
    This is a footnote.
`}/>

If the command is in the middle of a line, the argument needs to be
either on the same line or indented:

<Example src={`
  $$
    \\text: Quadratic formula:
    \\quad
    -b \\pm \\sqrt:
      b^2 - 4 a c
  $$
`}/>

Multiple arguments can be specified like a list:

<Example src={`
  \\subcaptionbox:
  - This is a caption.
    @=fig:example
  - \\centering
    \\includegraphics: example
`}/>

The final required argument can omit the bullet, reducing indentation:

<Example src={`
  \\resizebox:
    - \\linewidth
    - !
    Body
`}/>

`~` items get treated as optional arguments:

<Example src={`
  \\includegraphics:
  ~ width: 0.5\\textwidth
  - example
`}/>

## LaTeX Environments

`: env` is shorthand for `\begin{env} ... \end{env}`.
You must have a space after the colon, similar to [list bullets](#lists).
Indent the contents.

<Example src={`
  : theorem
    $p$ is prime.
`}/>

Required arguments can be specified with a colon:

<Example src={`
  : tabular: ccc
    1 & 2 & 3
`}/>

If indented, they must use a bullet (to separate the environment
from the content):

<Example src={`
  : tabular:
    - ccc
    1 & 2 & 3
`}/>

<Example src={`
  : theorem:
    ~ Main Result
    $p$ is prime.
`}/>

## Use Packages

`::use` is shorthand for putting `\usepackage{...}` in the preamble.

<Example src={`
  ::use amsmath
  ::use geometry: margin=1in, letterpaper
  ::use hyperref:
    pdftitle = Hello World
    pdfauthor = Me
`}/>

You can use many packages at once as an indented block:

<Example src={`
  ::use
    amsmath
    geometry: margin = 1in
    hyperref:
      - pdftitle = Hello World
      - pdfauthor = Me
`}/>

If you put `::use` after `\begin{document}`, it gets hoisted up to the preamble.

<Example complete src={`
  \\documentclass{article}
  \\begin{document}
  Here is the proof:
  ::use amsthm
  : proof
  \\end{document}
`}/>

## Raw TeX

`::tex` passes TeX through unchanged. Content can be on the same line
and/or on strictly indented lines.

<Example src={`
  ::tex \\foo{*raw* [text](url)}
  ::tex
    \\bar{@raw}
`}/>

## Preamble

`::preamble` puts LaTeX code in the preamble.
If it appears after `\begin{document}`, it gets hoisted up.

<Example complete src={`
  \\documentclass{article}
  \\begin{document}
  Here is the theorem:
  ::preamble \\newtheorem{theorem}{Theorem}
  : theorem
  \\end{document}
`}/>

## Automatic Document Boilerplate

Texlish automatically adds the following LaTeX boilerplate if needed:

* `\documentclass[11pt]{article}` as the first line.
  To use a different document class or option, specify it manually.
* `\begin{document}` before the first top-level line
  starting with apparent text content.
  Commands and braced text are considered valid preamble,
  while environments (in particular `abstract`) are considered text content.
* `\maketitle` after an added `\begin{document}`, if the document uses `\title`.
  Won't be added if you manually specify `\begin{document}`,
  so you can use this to override the automatic insertion of `\maketitle`.
* `\end{document}` as the last line.
  If you want uncompiled notes at the end of the file,
  feel free to specify `\end{document}` yourself to delimit them.

If Texlish gets the placement wrong, add the boilerplate manually,
and/or report a bug.

<Example complete src={`
  \\title: Texlish Demo
`}/>

<Example complete src={`
  % Comment
  ::use amsthm
  \\newtheorem{theorem}{Theorem}
  : theorem
`}/>

<Example complete src={`
  \\newtheorem:
    - theorem
    - Theorem
  - content
`}/>

<Example complete src={`
  Inside document
  \\end: document % manual separator
  Outside document
`}/>

For clarity, most examples in this documentation disable this feature
(via the `fragment: true` compiler option).

## Config

`::config` changes compiler options for the rest of the file:

<Example src={`
  $x_ij$
  ::config
    scriptGrouping = alphanumeric
  $x_ij$
`}/>

For a single option, `::config` can also be written on one line:

<Example src={`
  ::config scriptGrouping=alphanumeric
  $x_ij$
  ::config latexCompat
  $x_12$
  "straight quotes"
`}/>

Boolean options can be enabled with `optionName` and
disabled with `-optionName`:

<Example src={`
  ::config -markdownCompat
  [Texlish](https://texlish.org)
`}/>

Style config keys can be written in nested form:

<Example src={`
  *foo*
  ::config
    styles:
      * = \\textit
  *foo*
`}/>

or inline form with dots:

<Example src={`
  *foo*
  ::config styles.*=\\textit
  *foo*
`}/>

Supported config options are:

* `latexCompat`: flag setting equivalent to `scriptGrouping = none`,
  `-scriptParens`, and `-smartQuotes`
* `markdownCompat`: flag setting equivalent to maximize Markdown compatibility,
  currently `markdownBackticks`, `markdownHorizontalRules`, `markdownLinks`,
  `markdownLists`, and `smartQuotes`
* `markdownBackticks`: minimum number of backticks that enables
  [code spans and fenced code blocks](#code), or `0` to disable them;
  enabled by default as `1`
* `markdownHorizontalRules`: whether horizontal rule lines like `---` compile to
  `\medskip\hrule\medskip`; enabled by default
* `markdownLinks`: whether `[text](url)` compiles to
  `\protect\href{url}{text}`; enabled by default
* `markdownLists`: whether top-level Markdown-style bullets and numbered
  lists compile to LaTeX lists; enabled by default
* `smartQuotes`: whether straight `'` and `"` characters compile to
  TeX opening/closing quote ligatures; enabled by default
* `quotes`: output strings for opening/closing straight quote characters,
  used by [smart quotes](#smart-quotes)
* `scriptParens`: whether `_(...)` and `^(...)` group sub/superscripts;
  enabled by default
* `scriptGrouping`: [script grouping](#script-grouping) mode,
  one of `numeric` (default), `alphanumeric`, `alpha`, or `none`
* `styles`: styles for [emphasis](#emphasis), [code](#code),
  [horizontal rules](#horizontal-rules), or [label/ref](#label-ref);
  equivalent to `::styles`

You can also set config options globally in a
[project config file](/start#configuration).

## Script Grouping

By default, Texlish auto-groups multi-digit sub/superscripts:

<Example src={`
  $x^12y^42$
`}/>

Texlish also groups parenthesized sub/superscripts:

<Example src={`
  $x_(ij) + x^(i+j)$
`}/>

To change this behavior for the rest of the file, use [`::config`](#config):

<Example src={`
  ::config scriptGrouping = alphanumeric
  $x_12 + x_ij + x^12 + x^ij$
  ::config -scriptParens
  $x_(ij) + x^(i+j)$
`}/>

Allowed values for `scriptGrouping` are:

* `numeric` (default)
* `alphanumeric` (letters and digits group together)
* `alpha` (letters group together)
* `none` (no grouping, like LaTeX)

In LaTeX-compat mode, `scriptGrouping` gets set to `none`
and `scriptParens` gets set to `false`:

<Example src={`
  ::config latexCompat
  $x_12 + x_ij + x_(ij) + x^12 + x^ij + x^(ij)$
`}/>

## Version Requirements

If you're using a more recent or removed Texlish feature
(see the [changelog](https://github.com/edemaine/texlish/blob/main/CHANGELOG.md)),
you want to make sure that your collaborators have a matching version.
Use `::version` to check that the current Texlish version
satisfies a version range:

<Example src={`
  ::version >=0.1.1 <99999.0.0
`}/>

Without comparison operators, you can specify a version prefix and/or
use `x`, `X`, or `*` wildcards.  For example, the following are equivalent:

```texlish
::version 0.1
::version 0.1.x
::version 0.1.*
::version >=0.1.0-0 <0.2.0-0
```

Use `||` to accept multiple alternatives:

```texlish
::version 0.1 || 0.2
```

Comparisons should specify full `major.minor.patch` version numbers
(optionally with `-` prerelease), and can be prefixed by
`<`, `<=`, `>`, `>=`, or `=` (the default meaning of a bare full version).
Multiple comparisons and ranges separated by whitespace are combined with AND.
Then alternatives separated by `||` are combined with OR.
Comparisons follow [SemVer 2.0.0](https://semver.org/) rules.
Prerelease versions are included according to SemVer precedence
(like npm SemVer's
[`includePrerelease`](https://github.com/npm/node-semver?tab=readme-ov-file#prerelease-tags)
option).
