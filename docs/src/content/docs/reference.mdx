## Sections

Similar to Markdown headers, plus `*` for unnumbered sections.

<Example src={`
  # Introduction
  ## Background
  ### Aside
  #* Acknowledgments
`}/>

`!` goes up a level above section, while `.` goes down to the paragraph level:

<Example src={`
  !!# Beginning
  !# Introduction
  .# Results.
  .## Part 1.
`}/>

## Emphasis

Similar to Markdown emphasis.

<Example src={`
  *italic*
  **bold**
  ***bold italic***
`}/>

You can also redefine the meaning of these symbols:

<Example src={`
  ::styles
    * = \\textit
    ** = \\textsf
    *** = \\texttt
  *italic*
  **sans-serif**
  ***teletype***
`}/>

Equivalent `::config` form:

<Example src={`
  ::config
    styles:
      * = \\textit
      ** = \\textsf
      *** = \\texttt
  *italic*
  **sans-serif**
  ***teletype***
`}/>

To use the LaTeX character `*`, wrap it in braces
(so that pairs of emphasis characters aren't in the same group):

<Example src={`
  {*}not italic{*}
  {**}not bold{**}
`}/>

## Lists

Similar to Markdown lists, but with less strict requirements on indentation.

<Example src={`
  - This is an item.
  - This is a longer item that
    continues on the next line.
`}/>

<Example src={`
  * This is an item.
  * This is a longer item that
    continues on the next line.
`}/>

<Example src={`
  1. This is an item.
  2. This is a longer item that
    continues on the next line.
`}/>

<Example src={`
  The algorithm works as follows:
  1. Initialize
  2. For each step:
    * Do the step
    * Continue
`}/>

## Label/Ref

<Example src={`
  @=thm:main
  @thm:main
  @#thm:main
`}/>

If your label needs spaces or trailing punctuation, put it in quotes or braces:

<Example src={`
  @='thm main'
  @"thm main"
  @{thm main}
  @#'thm main'
`}/>

If you want to use a custom `\ref` system, such as `cleveref`, you can
override the meaning of these symbols:

<Example src={`
  ::styles
    @ = \\cref
    @# = \\cpageref
  @thm:main
  @#thm:main
  @thm:main,thm:other
`}/>

To use the LaTeX character `@` (that's not part of an [email link](#links)),
wrap it in braces:

<Example src={`
  To give feedback, {@}me
`}/>

<Example src={`
  [[paper1, paper2]]
`}/>

## Footnotes

Markdown-style footnotes define their content once with `[^id]:` and insert
the first marker with `[^id]`.

<Example src={`
  This is a problem[^false], but not too bad[^true].
  [^false]:
    This is actually not true.
    See Figure @fig:example.
  [^true]: This is actually true.
`}/>

The first marker expands to `\footnote{\label{footnote:id} ...}`. Later markers
re-use the same footnote number with `\footref{footnote:id}`, and
`@^id` references that generated label directly as a number (no superscript).

<Example src={`
  This is first[^count].
  [^count]: But who's counting?

  See footnote @^count for details.[^count]
`}/>

Numeric IDs are disposable: all matching markers since the previous definition
bind to the next matching definition in document order. This lets each
paragraph re-use simple IDs like `[^1]`, without having to think up a name.

<Example src={`
  First paragraph[^1], again[^1].
  [^1]: First note.

  Second paragraph[^1].
  [^1]: Second note.
`}/>

## Links

Similar to Markdown automatic links, you can write URLs and email addresses
in angle brackets.

<Example src={`
  <https://texlish.org>
  <edemaine@mit.edu>
`}/>

Texlish even produces a correct `mailto:` link in the common brace format
for writing multiple email addresses at the same domain:

<Example src={`
  <{edemaine,mdemaine}@mit.edu>
`}/>

To customize the visible text of a link, use Markdown-style inline links:

<Example src={`
  [Texlish](https://texlish.org)
`}/>

Texlish uses `\protect` in case links appear in a moving argument.

## Commands

`\command:` makes it easier to specify commands with arguments.
The argument can be on the same line and/or on indented lines.

<Example src={`
  \\title: The Paper \\\\
    Subtitle
`}/>

<Example src={`
  \\footnote:
    This is a footnote.
`}/>

If the command is in the middle of a line, the argument needs to be
either on the same line or indented:

<Example src={`
  $$
    \\text: Quadratic formula:
    \\quad
    -b \\pm \\sqrt:
      b^2 - 4 a c
  $$
`}/>

Multiple arguments can be specified like a list:

<Example src={`
  \\subcaptionbox:
  - This is a caption.
    @=fig:example
  - \\centering
    \\includegraphics: example
`}/>

`~` items get treated as optional arguments:

<Example src={`
  \\includegraphics:
  ~ width: 0.5\\textwidth
  - example
`}/>

## Environments

`: env` is shorthand for `\begin{env} ... \end{env}`.
You must have a space after the colon, similar to [list bullets](#lists).
Indent the contents.

<Example src={`
  : theorem
    $p$ is prime.
`}/>

Required arguments can be specified with a colon:

<Example src={`
  : tabular: ccc
    1 & 2 & 3
`}/>

If indented, they must use a bullet (to separate the environment
from the content):

<Example src={`
  : tabular:
    - ccc
    1 & 2 & 3
`}/>

<Example src={`
  : theorem:
    ~ Main Result
    $p$ is prime.
`}/>

## Use Packages

`::use` is shorthand for putting `\usepackage{...}` in the preamble.

<Example src={`
  ::use amsmath
  ::use geometry: margin=1in, letterpaper
  ::use hyperref:
    pdftitle = Hello World
    pdfauthor = Me
`}/>

You can use many packages at once as an indented block:

<Example src={`
  ::use
    amsmath
    geometry: margin = 1in
    hyperref:
      - pdftitle = Hello World
      - pdfauthor = Me
`}/>

If you put `::use` after `\begin{document}`, it gets hoisted up to the preamble.

<Example complete src={`
  \\documentclass{article}
  \\begin{document}
  Here is the proof:
  ::use amsthm
  : proof
  \\end{document}
`}/>

## Raw TeX

`::tex` passes TeX through unchanged. Content can be on the same line
and/or on strictly indented lines.

<Example src={`
  ::tex \\foo{*raw* [text](url)}
  ::tex
    \\bar{@raw}
`}/>

## Preamble

`::preamble` puts LaTeX code in the preamble.
If it appears after `\begin{document}`, it gets hoisted up.

<Example complete src={`
  \\documentclass{article}
  \\begin{document}
  Here is the theorem:
  ::preamble \\newtheorem{theorem}{Theorem}
  : theorem
  \\end{document}
`}/>

## Automatic Document Boilerplate

Texlish automatically adds the following LaTeX boilerplate if needed:

* `\documentclass[11pt]{article}` as the first line.
  To use a different document class or option, specify it manually.
* `\begin{document}` before the first top-level line
  starting with apparent text content.
  Commands and braced text are considered valid preamble,
  while environments (in particular `abstract`) are considered text content.
* `\maketitle` after an added `\begin{document}`, if the document uses `\title`.
  Won't be added if you manually specify `\begin{document}`,
  so you can use this to override the automatic insertion of `\maketitle`.
* `\end{document}` as the last line.
  If you want uncompiled notes at the end of the file,
  feel free to specify `\end{document}` yourself to delimit them.

If Texlish gets the placement wrong, add the boilerplate manually,
and/or report a bug.

<Example complete src={`
  \\title: Texlish Demo
`}/>

<Example complete src={`
  % Comment
  ::use amsthm
  \\newtheorem{theorem}{Theorem}
  : theorem
`}/>

<Example complete src={`
  \\newtheorem:
    - theorem
    - Theorem
  - content
`}/>

<Example complete src={`
  Inside document
  \\end: document % manual separator
  Outside document
`}/>

For clarity, most examples in this documentation disable this feature
(via the `fragment: true` compiler option).

## Config

`::config` changes compiler options for the rest of the file:

<Example src={`
  $x_ij$
  ::config
    scriptGrouping = alphanumeric
  $x_ij$
`}/>

For a single option, `::config` can also be written on one line:

<Example src={`
  ::config scriptGrouping=alphanumeric
  $x_ij$
  ::config latexCompat
  $x_12$
`}/>

Boolean options can be enabled with `optionName` and
disabled with `-optionName`:

<Example src={`
  ::config -markdownCompat
  [Texlish](https://texlish.org)
`}/>

Style config keys can be written in nested form:

<Example src={`
  *foo*
  ::config
    styles:
      * = \\textit
  *foo*
`}/>

or inline form with dots:

<Example src={`
  *foo*
  ::config styles.*=\\textit
  *foo*
`}/>

Supported config options are:

* `latexCompat`: flag setting equivalent to `scriptGrouping = none`
  and `scriptParens = false`
* `markdownCompat`: flag setting equivalent to maximize Markdown compatibility,
  currently `markdownLinks`
* `markdownLinks`: whether `[text](url)` compiles to
  `\protect\href{url}{text}`; enabled by default
* `scriptParens`: whether `_(...)` and `^(...)` group sub/superscripts;
  enabled by default
* `scriptGrouping`: [script grouping](#script-grouping) mode,
  one of `numeric` (default), `alphanumeric`, `alpha`, or `none`
* `styles`: styles for [emphasis](#emphasis) or [label/ref](#label-ref);
  equivalent to `::styles`

You can also set config options globally in a
[project config file](start#configuration).

## Script Grouping

By default, Texlish auto-groups multi-digit sub/superscripts:

<Example src={`
  $x^12y^42$
`}/>

Texlish also groups parenthesized sub/superscripts:

<Example src={`
  $x_(ij) + x^(i+j)$
`}/>

To change this behavior for the rest of the file, use [`::config`](#config):

<Example src={`
  ::config scriptGrouping = alphanumeric
  $x_12 + x_ij + x^12 + x^ij$
  ::config -scriptParens
  $x_(ij) + x^(i+j)$
`}/>

Allowed values for `scriptGrouping` are:

* `numeric` (default)
* `alphanumeric` (letters and digits group together)
* `alpha` (letters group together)
* `none` (no grouping, like LaTeX)

In LaTeX-compat mode, `scriptGrouping` gets set to `none`
and `scriptParens` gets set to `false`:

<Example src={`
  ::config latexCompat
  $x_12 + x_ij + x_(ij) + x^12 + x^ij + x^(ij)$
`}/>

## Version Requirements

If you're using a more recent or removed Texlish feature
(see the [changelog](https://github.com/edemaine/texlish/blob/main/CHANGELOG.md)),
you want to make sure that your collaborators have a matching version.
Use `::version` to check that the current Texlish version
satisfies a version range:

<Example src={`
  ::version >=0.1.1 <99999.0.0
`}/>

Without comparison operators, you can specify a version prefix and/or
use `x`, `X`, or `*` wildcards.  For example, the following are equivalent:

```texlish
::version 0.1
::version 0.1.x
::version 0.1.*
::version >=0.1.0-0 <0.2.0-0
```

Use `||` to accept multiple alternatives:

```texlish
::version 0.1 || 0.2
```

Comparisons should specify full `major.minor.patch` version numbers
(optionally with `-` prerelease), and can be prefixed by
`<`, `<=`, `>`, `>=`, or `=` (the default meaning of a bare full version).
Multiple comparisons and ranges separated by whitespace are combined with AND.
Then alternatives separated by `||` are combined with OR.
Comparisons follow [SemVer 2.0.0](https://semver.org/) rules.
Prerelease versions are included according to SemVer precedence
(like npm SemVer's
[`includePrerelease`](https://github.com/npm/node-semver?tab=readme-ov-file#prerelease-tags)
option).
